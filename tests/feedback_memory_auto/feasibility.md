# Stage 1: FeedbackMemory feasibility, before implementation

Baseline master8443a0d19a88aff7a5900011bccf386daf146945. Decision: proceed with the isolated attribute-only experiment; no clear semantic incompatibility found and a modest local logic saving is credible. This is not a measured optimization result.

FeedbackMemory (rtl/VM2413/feedbackmemory.vhd:41–92) stores9×10=90 bits: a sign bit plus nine magnitude bits (VM2413 SIGNED_LI_TYPE/LI_TYPE and conversion functions). Legal CH_TYPE addresses are0–8. There is one independent write address and one read address, with one common rising-edge clock and write enable. No asynchronous payload read or asynchronous payload reset exists. Reset asynchronously restarts init_ch only and holds the output. The first nine rising edges after release clear one word per edge, overriding normal writes; output still reads the pre-edge selected word. Power-up/unwritten contents are unspecified. Ordinary writes and initialization collisions both return OLD_DATA. Read output is registered: address must be stable before the rising edge; output holds between clocks and during reset. Read and write may target different addresses. All1024 bit patterns, including signed zero representations, must remain intact.

OutputGenerator Fmem (outputgenerator.vhd:125) writes channel-averaged feedback from the even/modulator slot at stage3 (lines172–179). Operator consumes fdata.sign/value (operator.vhd:104–127) and prefetches channel addresses (lines142–144). OPLL wires the two modules through faddr/fdata (opll.vhd:235–237,347–353). The memory itself is clocked continuously, not only on clkena; writes are controlled by the producer and reset sequencer. Preserve this detail during freeze/save-load tests. A feedback dependency exists algorithmically, but this bank is sequential storage, not a combinational loop.

The explicit `attribute ramstyle of data_array : signal is "logic";` at line57 blocks hard-memory implementation. Its removal should permit a simple dual-port synchronous RAM with mixed-port OLD_DATA semantics. This is supported by the actual access structure; it is not an assumption that all storage deserves M10K. Actual AUTO mapping and read-during-write behavior must be verified with Quartus and vendor-model simulation before claiming success. MLAB suitability must be taken from the fitted report, not presumed.

Existing synthesis_structure/review.md reports local75.7 placed/51.7 needed ALMs and106 registers at baseline. A90-bit bank is small: one nominal10240-bit M10K would be under1% payload utilization. Baseline uses487/553 M10Ks; an independent one-block conversion would use488, leaving65. That cost may be acceptable for a modest ALM reduction, but only whole-design A/B measurements can decide. No PhaseMemory or RegisterMemory change is included.

Lessons: PhaseMemory AUTO passed functional checks and repeated area gains, but routing/timing varied by seed. RegisterMemory AUTO was functionally correct yet lost baseline video retiming, reducing HDMI setup margin to19ps. Increasing physical-synthesis effort to Extra did not recover it. This experiment therefore uses original Normal-effort settings, checks retiming transformation counts/actual HDMI paths, and will not accept area savings caused by unexplained loss of video retiming. A failed seed1 acceptance gate is unfavorable and stops before seed2; seed2 is run only for a promising first result. No forced block type, constraint relaxation, fitter-control change or implementation fix is authorized here.

Planned functional qualification: exhaustive9×9 legal port pairs and all1024 payload patterns against an independent old-data/latency scoreboard; reset interruptions after0–9 initialization writes; both write-enable states; read/write collisions and differing addresses; randomized retained contents; Quartus-mapped bank checks, full OPLL and real savestate-controller regressions. This is exhaustive port/payload transition coverage, not enumeration of all2^90 global stored states or a formal proof of the mapped netlist. RTL equivalence additionally follows by construction because only an implementation attribute is removed.
