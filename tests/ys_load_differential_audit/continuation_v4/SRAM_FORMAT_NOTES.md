# Narrow format considerations, pending playable-scene qualification

This is a design note, not an implemented correction or a causality result.

An isolated SRAM candidate must preserve all physical addresses 0000–7FFF, independent of mapper enable/bank flags. Existing master DMA counters and the ordinary SRAM DDR region 0D01–1D00 already accommodate 32 KiB. The copy must not run in System E (overlapping memory layout), SC RAM modes, or EEPROM configurations. Master's existing controller interface does not expose all of those eligibility signals; a test-only ordinary-cartridge eligibility input can represent the known fixture, but a production proposal would need real configuration wiring and exclusion tests. The legacy paths must remain unchanged when the extension is absent.

A descriptor placed only in a previously unused DDR word is **insufficient**: an old writer may overwrite the same slot without clearing that word, leaving a stale complete-SRAM marker. Eligibility must also be indicated in a word every legacy writer actually overwrites. Current master and public FM v1 overwrite CPU word5 bits63:38 with zero. A carefully validated extension there can invalidate old/unmarked saves reliably; it must distinguish SRAM completeness from predecessor-context presence so SRAM-only B does not enable CPU correction C. The v3 experimental CPU owner/version must not silently gain a second meaning. Historical video's 484312 tag must not be imported wholesale: current public FM's video-tag/descriptor rules differ.

The writer should initially clear completeness and publish it only after the full payload is drained, keeping the framework change detector as the final save commit. Both combinational DDR command generation and sequential helper writes need the same behavior. The reader must check owner, version, feature flags, reserved bits, eligibility, and old-format bypass before restoring memory. Unmarked old snapshots retain their old conditional SRAM behavior; their missing SRAM cannot be recovered by a new reader. Old readers ignore the new completeness/context fields and cannot guarantee exact continuation of a new snapshot.

Theoretical additional transfer for a currently disabled mapper is 32768 bytes =4096 DDR64 words per SAVE and per LOAD. Fixed 96-KiB file size need not grow. A one-byte-per-host-clock DMA has a lower bound of about0.610 ms at53.69MHz; DDR read latency, backpressure and commit sequencing add time. These are theoretical values, not measured candidate timings. The existing900000-clock flush is unchanged. Existing physical SRAM and DDR storage can be reused; extra logic is eligibility, metadata, validation and commit control. No measured ALM/register/timing delta is available, and no Quartus build is authorized.
