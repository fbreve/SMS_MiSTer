# Current v14 state and consumer inventory

This inventory refers to committed RTL, not the historical v13 investigation. `inventory.json` contains every named declaration, assignment and consumer line, plus relevant current restart wiring. A power-up value absent from RTL is explicitly unspecified; initialized runtime checks must establish known values before using it as evidence.

All VDP devices capture their combinational architectural vector post-T at ARM. Background history has no payload. On accepted T, normal enables apply; ss_freeze then asserts. Guest VDP/pixel/sprite enables are zero through transport, peripheral restore, CPU preparation and phase installation. First ordinary enable follows phase/beam commit. The old_HL host-clock sampler and one-clock data_write deassertion are exceptions to simple CE hold.

Background fields are grouped only where width, reset, update and consumer rules coincide. The candidate classifications above describe the initial inventory, not the final disposition. The text_history witness confirms that ordinary data0..3 and shift0..3 are POTENTIALLY FUTURE-RELEVANT (in fact demonstrably future-relevant) while text mode is active: they hold across text lines and a later visible Mode4 switch consumes them. The attribute and other inactive-mode fields require a focused minimal-history analysis before a fix; this investigation does not claim every candidate bit is necessary. The whole G05 refill hypothesis is rejected.

Final G02/G03/G04 classifications follow the bounded consumer proofs and dynamic evidence in review.md. In particular cpu_write_data is OVERWRITTEN BEFORE OBSERVATION once pending-write exclusion is established; IRQ_n is RECONSTRUCTED before its first interrupt consumer. No inventory row alone grants closure.
