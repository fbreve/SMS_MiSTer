# Consumer-order arguments on committed v14

These arguments concern functional observations at the production accepted boundary. They do not assert that every discarded register equals the uninterrupted reference throughout transport. Dynamic results and final dispositions belong in review.md.

## Common timing premise

The production divider supplies VDP enables every five host clocks. The fastest supported CPU cadence is ten; ordinary CPU cadence is fifteen. System E Pause can suppress CPU execution or temporarily permit ordinary coherent capture-seeking execution; it does not accelerate CPU strobes or stop the VDP. Accepted normal-fetch M1/MREQ/ISet00 cannot overlap a CPU I/O or memory-write transaction. Requests in those transactions wait for the next eligible fetch. A suppressed-T capture leaves more preparation steps before instruction completion, never fewer.

Accepted T finishes normally. v14 holds guest VDP/pixel/sprite execution immediately after T, captures post-T device state at ARM, reconstructs only historical CPU fetch steps while those domains remain held, and installs saved phase/beam before continuation. A transport wall clock is not a guest clock. See restart_assumptions.md and the first-enable assertions in each integrated fixture.

## G02 pending status clear

Only a qualified status-read edge sets reset_flags during ordinary execution. The VDP consumes that Boolean on the next enabled VDP clock and clears it unless another status-read edge is detected. Detection and consumption therefore require at most two VDP opportunities from the CPU read assertion: at most ten host clocks. The non-fetch I/O cycle must finish and the next opcode fetch must be set up before the accepted fetch T2. Even a conservative two-fast-CPU-opportunity lower bound is twenty host clocks; the actual ordinary IN path is longer. No new I/O transaction can preempt that drain at an accepted normal fetch. The clone's additional write-edge sampling cannot postpone consumption past this bound.

The reset-generated true value likewise drains before an active-session accepted fetch; reset and download are not active-session captures. Paused seeking cannot shorten the physical interval from the preceding transaction. Thus an outstanding status-clear event is absent at capture; normalization to false does not lose an event. Frame, line, collision and overflow use the same pending-clear Boolean, so their different flag-setting conditions do not create a new pending-clear lifetime.

Bit103 is actually written in the architectural VDP record. Consequently two post-T states with different reset_flags cannot have equal complete current images. A distinction before T that is consumed at T is not missing post-T history. Natural pending-clear scans and earliest-post-IN captures corroborate this boundary argument rather than substituting for it.

## G03 pending transactions and edge priming

Data/direct writes produce a one-host-clock data_write pulse. RAM consumes it on the following host edge; pending address increment drains on a subsequent VDP opportunity. Read-address setup is the longest named queue: detect command, set read pending; next VDP opportunity sets increment; the following one increments and captures registered RAM output. The maximum is three VDP opportunities from CPU strobe assertion, fifteen host clocks. The conservative twenty-clock lower bound to the accepted fetch already exceeds it. Real T80 OUT/IN and memory-write completion have additional fetch setup time. Tight block I/O does not interleave a new strobe inside this bound. The clone's extra edge observation only supplies earlier processing opportunities.

At capture no data_write, increment, or incomplete read is needed to finish an earlier transaction. Address, address_ff, CRAM low-byte latch and read-ahead data are separately serialized. Partial control-word setup is intentional architectural state, not a drained transaction: the low address byte and address_ff survive so the next control OUT completes exactly once.

The VDP-facing RD/WR are inactive for a CPU opcode memory fetch, including private historical T1/T2. The direct-write selector also sees WR inactive. Live-level priming therefore cannot invent a new port edge. The first subsequent genuine data/direct write replaces cpu_write_data before RAM consumes its pulse. A stale differing write-data value with no write pulse has no consumer; the SMS CRAM upper-bit-alias pair tests that distinction with equal complete images.

The registered D_out, although not one of the seven original named items, is another omitted bus latch. Its arbitrary old value while RD is initially asserted is not the CPU result. A new qualified read replaces it within five host clocks; the T80s DI_Reg sample at enabled TState2 is at least one CPU period later. The accepted fetch and historical replay consume ROM, not VDP D_out. Current tests observe the actual DI_Reg sampling edge, including wait samples, and compare sample count/value plus CPU architecture/RAM. Counts are latch samples, not deduplicated IN instructions.

old_HL samples every host clock and converges to the current pin independently of CE. F11 direction settlement precedes F07 latch installation; simultaneous ss_regs_set has priority over a new HL capture. Private CPU replay issues no VDP I/O change. The current-pin contract and an identical logical future HL sequence are retained. The real T80 HCounter case and current-production F07 priority tests exercise saved latch restoration, subsequent genuine edges and guest reads; they are not arbitrary rewind of a physical peripheral.

## G04 serialized delay, IRQ reconstruction and x history

The fourteen collision-delay bits are literal v14 sprite-record fields. Post-T source, delay and flags all remain held during preparation; ordinary enabled transitions resume in the historical phase order. Any distinction in the post-T delay changes the complete image, so the historical v13 zero-normalization concern has been superseded. Current pending-delay/late/overflow cases and the every-host-clock oracle test the remaining temporal claim.

Every accepted raw CPU event is also a VDP event. At post-T, last_x0 is therefore the pre-T beam parity. For phase0/10/20 the pixel advanced, so it is the opposite of saved post-T x parity; for phase25 the pixel did not advance, so it equals saved x parity. Both phase and post-T beam are in v14. There is no independent same-image distinction in accepted last_x0. The reader currently primes the raw beam rather than applying that formula, but the first resumed VDP opportunity overwrites it. Its only consumers are x485/486; saved x<=256 excludes either consumer before overwrite. The native oracle allows this distinction only before that first VDP opportunity and then requires exact equality.

IRQ_n is recomputed from enabled saved flags, mask and irq_delay. At positive delay it remains deasserted; at zero the next enabled VDP transition establishes the asserted level. If a just-expired countdown could distinguish the old registered pin from the formula during the initial hold window, no CPU interrupt decision consumes that distinction: private replay is historical T1/T2, and Mode0 MC1 cannot end before T4. The real unchanged T80_MCode superset check exhausts 2,359,296 combinations (all opcodes/flags, ISet0..2, XY0..2 and both interrupt-cycle inputs) and finds minimum4. This is a combinational lemma, not millions of claimed reachable CPU states.

The first ordinary VDP opportunity is five host clocks after canonical release. The earliest ordinary CPU opportunity can coincide with it, but is only T3; T4 is at least another ten clocks later. Both reference and restored IRQ are therefore equal before the first possible interrupt-acceptance consumer. Subsequent IRQ transitions use equal restored flags/delay and equal logical CE/mode/status-read inputs. Enabled line/frame handler tests separately compare actual CPU and guest RAM. System E's production CPU IRQ source is VDP2; VDP1's status/IRQ state remains separately observable through its port and output. No AND of the two pins is used in the enabled System E witness.

## G05: why a stable-mode refill argument is insufficient

Horizontal reset and the text bootstrap can repair active pipelines before ordinary visible lines. That is a conditional result, not a proof for future mode switches. During text mode, ordinary plane/data/attribute registers hold their previous nontext history. ss_restore clears them. A later change of R0 can immediately select Mode4 while visible, before a complete fresh ordinary tile load. The converse inactive-text-history question also requires review in any fix design.

The text-history experiment uses real CPU writes and past R9=0/1 inputs, restores identical current R9 after entering text, captures naturally in VBlank, then switches a single register back to Mode4 at the first visible line. The background probe is read-only. It observes retained history; it never installs a side record or forces an internal background register. Runtime evidence confirms equal complete known v14 images, seven differing visible reference pixels, and nine corrupted visible pixels on each of six actual LOAD replays. See pair_metrics.json and review.md for the independent image and suffix hashes.

## Equivalences used to limit Cartesian testing

PAL and 192/224/240 modes alter beam/IRQ event conditions, not CPU/VDP cadence or the pending-bus/clear lifetime. Those conditions, modes, counters and beam are serialized; G02/G03 drain arguments therefore share one timing bound. G04's delay transition and IRQ-consumer ordering likewise do not depend on region, height or sprite-slot count. Different collision sources are covered by the retained G06 contract; the new scalar/status tests do not reopen that closure. The same VDP entity implements both System E chips; distinct memory/status/direct-write cases verify routing and independent records. GG crop is not used to exclude collision/status observations. These equivalences do not close G05 across inactive mode histories, and do not claim physical SDRAM/decryption, full WRAM topology, mixer/FM or cartridge-RAM coverage.
