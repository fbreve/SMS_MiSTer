## 1–3. Architecture, lifetime, restore semantics

`mapper_detect.vhd` owns static media identification and runtime inference. `mapper_ctrl.vhd` owns selected mapper/banks and the first-write 4PAK detector. `memory_decode.vhd` turns those choices into physical ROM addresses and Dahjee cartridge RAM access. `system.vhd:1480` packs current state into the64-bit mapper word. The inventory records every persistent detector/controller item, width, reset/update/clear, consumer, serialization and addressing effect, distinguishing actual storage from combinational outputs and download-only scanner scratch.

Detection is **not globally finalized** by the65,535-clock startup window. While the old16-bit timer is less than65535, bank/Sega evidence and Wonder Kid recognition update on host clocks. At old timer65534, lack of bank evidence selects linear mapping for4 ROM pages or Sega-locked banking for6 pages. Outside that window, eligible Dahjee and first4PAK recognition still execute. Thus a late savestate is not a justified exclusion. A Sega write after the window does not record new evidence; a Sega write within it continues suppressing those later detectors indefinitely.

Sega evidence is a sticky exclusion flag, not the selected Sega mapper itself. Bank evidence is relevant only before the fallback decision. Already selected flags are generally sticky until reset/restore, but there is no universal “mapper finalized” flag: higher-priority selection and independently running Dahjee inference can still affect mapping. `mapper_codies_lock` specifically protects Codemasters detection. The misleadingly named `lock_mapper_B` has no decision/address consumer in the current design; its packed compatibility bit does not finalize detection.

Every production `mapper_set` source is the savestate controller. Runtime mapper selection uses direct detector/controller assignments, reset uses RESET_n, BIOS handoff uses bootloader_n, and media replacement holds reset while download metadata is rebuilt. The top connects the controller strobe to system; system fans it out to detector, banking, System E IO and relevant Evolution/board state. There is no normal-runtime mapper-change caller that needs historical evidence cleared by that strobe.

At `savestates.sv` ST_WAIT_RESTORE_BOUNDARY, the controller issues `mapper_in=mapper_snap` and `mapper_set=1` before CPU/VDP restore. The detector restores resolved flags (or clears their overloaded Evolution interpretation for tagged E132), then assigns timer65535, bank evidence0, Sega evidence0 and Wonder Kid count0, regardless of freeze. It does not restore detection history. Banking separately restores existing mapper/bank fields. The code makes this a terminal-window normalization; attributing a deliberate historical rationale beyond that is inference, not established intent. Reset/BIOS initialization legitimately clear history because they start a new detection lifetime. LOAD resumes an old lifetime and cannot use that initialization policy.

## 4. Accepted-boundary reachability

All history in the fixtures is accumulated by actual module input activity. No detector value, mapper flag or controller state is forced. The sole force bypasses UI cooldown between operations. The real controller still requires native cpu_ce, M1 low, MREQ low, ISet00, VBlank, x<256 and idle storage.

The scripted replay tests complete the production SAVE/LOAD/DDR FSM. Prefixes use30-host-clock memory writes. A separate183-capture sweep covers61 adjacent request clocks around the deadline with no evidence, Sega evidence and bank-only evidence; Tcl only observes internal timer/history. These are183 accepted capture samples, not183 completed saves/loads. Timer values on both sides of the deadline are observed, with partial values65483/65498/65513/65528 and saturated65535 depending on native CE alignment.

Independently, actual T80 plus production `video.vhd` executes a cartridge program that writes FFFD=0 and A000=3, then loops. The controller accepts both a mature point and an early BIOS-handoff point during actual video VBlank. The early point is912 host clocks after handoff at x91/y192; the mature point is66912 clocks after handoff at x193/y211. Both preserve Sega evidence1 and bank2=3. Actual T80 uninitialized registers remain X where production does not initialize them; reachability assertions use known bus, mapper and video fields. The full load comparison uses deterministic bus traces, not a commercial-ROM or full real-CPU load replay.

## 5–7. Heuristics and causal family

**Dahjee:** runtime recognition requires SMS (gg0), no manual force, BIOS handed off, not frozen, memory WR, no Sega evidence, AB at ROM bytes0/1, and address2000–3FFF except3FFE. One eligible host sample selects it; there is no count threshold. The separate download-time Dahjee scanner requires a blank2000–3FFF region, more than10 relevant stores, and count23>=countDEF. It is retained for the same media and is not erased on LOAD; no static-scanner defect is attributed to F13. Cases0/2/4 cover historical suppression, no evidence, and after selection. Case11 covers a Sega write too late to record exclusion evidence.

**4PAK:** the first eligible3FFE memory write selects4PAK and initializes its registers. The trigger is outside the timer window but requires no Sega evidence and must reach its branch after Janggun, EEPROM, System E/SC/Castle/linear/Dahjee/Sega-locked, existing4PAK and active Zemina priorities. There is no 4PAK count, multistep confidence threshold, or requirement for several distinct writes. Cases1/3/5 cover before selection with/without exclusion evidence and after selection. The sweep measures native clock boundaries; the future trace starts with the exact decision-causing write, followed by a mapped read. Subsequent7FFF/BFFF writes are architectural banking, not additional recognition history.

**Other affected decisions:** early-window LOAD can prevent32K linear fallback,48K Sega-locked fallback, and Wonder Kid recognition. Cases6/7/9 reproduce all three as different cartridge bytes. Case8 confirms an already recognized Wonder Kid selection survives when the discarded context still has that selection. Case10 proves bank evidence is independently non-reconstructable before fallback, even though the current loader’s already-terminal timer masks its loss in that specific restored replay.

**Additional reconstructable edge history:** `mapper_ctrl.mapper_wonderkid_prev` is primed from the effective mapper flag visible before mapper_set. That flag belongs to the discarded context. In `edge.log`, a recognized Wonder Kid snapshot contains bank2=3; only the discarded machine is reset before LOAD. Mapper_set restores the resolved flag and bank, but primes prev=0. The next clock sees an apparent rising recognition edge, initializes banks and overwrites bank2 with0. A second LOAD sees the flag already1 and preserves bank2=3. This is directly within F13's restore/detection-history scope; it is not missing architectural bank serialization. The existing saved resolved flag suffices to reconstruct the edge tracker correctly.

The same root cause applies to `bootloader_n_prev`. Production system restores bootloader_n from mapper bit54 on mapper_set, while mapper_ctrl primes its previous value from the discarded current boot input. `boot_edge.log` saves a handed-off cartridge with bank2=3, makes only the discarded context BIOS-active, and restores via the actual controller. The following false BIOS-handoff edge overwrites bank2 with2, even while frozen; read8123 returns02 instead of03. A second LOAD returns03. The fixture mirrors the production one-clock boot restore assignment; the already saved bit54 (Evolution's defined active-cart1) supplies the correct reconstructed previous value. RESET_n itself is not snapshot-restored and needs no new payload.

Wonder Kid’s “two writes” comment means two host-clock samples of the same eligible8000 write. T80’s minimum native enable separation is10 host clocks (15 ordinary SMS); WR remains stable between enables. Therefore the count1 intermediate cannot be accepted at a later M1 while its window remains open. At accepted boundaries, count0 normalization is equivalent given saved resolved flags, restored timer and unchanged media. If a write straddles window expiration, count1 becomes unconsumed terminal history. See the explicit exclusion argument in the inventory. This investigation does not recommend blindly serializing that counter, download scanners, debug flags, or media fingerprints.

## 8–12. Dynamic results and minimal reproducer

Each of twelve replay cases completes one SAVE and two LOADs. SAVE ONLY is checked against the independently held/reference mapper and then the same future trace. LOAD starts from a naturally replayed reference prefix at the recorded capture age, asserts the reference architectural mapper word equals the saved word, perturbs only the discarded machine, loads through production mapper_set, and applies the same suffix. The second LOAD follows additional runtime bus activity and must reproduce exactly the first restored result. The defect is deterministic, not dependent on residual current history.

Two additional edge-history replays each complete one SAVE and two LOADs. Wonder Kid: saved word `4840000003030000`, first restored word `4840000003000000`, ROM C123/0123, data03/00. BIOS handoff: saved word `0040000003030100`, first restored word `0040000003020100`, ROM C123/8123, data03/02. Both second LOADs of the identical snapshot return03. Thus the twelve initial cases show stable repeated-load defects, while the broader F13 edge-history mechanisms explicitly depend on discarded runtime state. ## 13–18. Reconstruction, minimal future architecture, versioning and legacy

The non-injective pairs are dynamically checked. In cases0/1, the no-evidence peer skips a same-value FFFD=0 write, with all currently packed mapper fields equal. The reference has Sega evidence1 and peer0; their identical suffix produces different mapper flags and different ROM bytes. In case10,4000 writes set bank evidence without changing current bank state; the equal-word no-evidence peer makes a different terminal fallback decision. These differences do not enter any other v8 header field: those interfaces are identical in the bus-level fixture, and a same-value mirrored WRAM write can leave its stored byte unchanged. This is a proof about identical modeled v8 architectural inputs and future mapper behavior, not a claim that two complete commercial-game CPU runs were compared byte-for-byte.

Consequently required history cannot be recovered uniquely from current v8 mapper flags/banks or ROM identity. Different remaining timer values can likewise share all packed architectural fields while permitting different future8000 recognition. A current mapper type is not a unique encoding of its detection lifetime.

| Candidate | Assessment |
|---|---|
| A: serialize history | Correct for required history belonging to T; must capture it coherently with mapper state and restore it before guest execution |
| B: merely stop clearing current history | Incorrect: current post-save history may include discarded Sega/bank writes and elapsed deadline; retaining it does not restore T |
| C: reconstruct all from v8 | Impossible for demonstrated non-injective Sega/bank pairs and remaining-window progress |
| D: distinguish restore from initialization | Useful interface semantics, but requires actual saved history; a new restore strobe alone cannot recover T |
| E: hybrid | Recommended: serialize timer16 + Sega evidence1 + bank evidence1; reconstruct/normalize count0 at accepted M1; prime Wonder Kid and BIOS-handoff edge history from restored effective selection/boot state; retain static same-media metadata and already serialized flags/banks |

The smallest straightforward fixed-width history representation is18 bits. Bank evidence can be normalized after the terminal decision, but must be retained for an active4/6-page candidate. Sega history remains necessary whenever later Dahjee/4PAK guards can consult it. No “already finalized” normalization should be inferred solely from lock_B, timer saturation, or an arbitrary selected mapper flag. A future fix must sample flags/history at one coherent logical point, including the65534 decision edge; this investigation does not change capture timing.

Additional serialized information is required. Recommend a tagged new history extension and the next format version (v9 under the current v8 scheme), with validation and deterministic fallback for missing/malformed extensions. Existing unmodified v8 has no encoding for this history. An independently versioned extension tag could technically supply the version discriminator instead of changing the main marker, but that is still a protocol extension; it does not make existing v8 states lossless. No payload or version has been changed here.

Legacy states cannot promise exact original detection replay. Keep already saved resolved mapper/bank state. A deterministic compatibility policy can normalize missing timer to65535, Sega/bank evidence to0 and count to0, documenting the same known limitations as current legacy behavior. Do not manufacture positive Sega evidence to pretend historical knowledge. An alternative policy that freezes the saved selection needs an explicit new semantic latch and changes future behavior for genuinely provisional states; it is not an exact reconstruction either. New-format loads must restore T’s evidence even after arbitrary post-save activity. A future implementation should explicitly test both snapshot-history directions and terminal-edge ordering.

## 19–20. Existing mapper fixes and regressions

System E portF7 lives in mapper byte0; mapper_ctrl intentionally skips restoring generic bank0/pak4_reg0 for System E, while IO consumes the same restore strobe. Evolution uses its own bank byte layout and E132-tagged extra state; detector flag positions must not reinterpret launch-record bits. F13 reproduces in ordinary SMS after exact current mapper/bank restoration, so it is causally distinct from those fixes. Their existing directed checks are rerun, including Evolution launch/restore, System E bank0 exclusion and EEPROM precedence.

Regression results are validated in `results.json`: current directed mapper/banking checks; SRAM routing and mapper-memory controls; EEPROM protocol,24 full DDR cases and persistence;60 SC RAM DDR size/case combinations; F07 controller-format and System E integration; F08 real-time MD6; F09 Master Tap; F10 paddle; F11 lightgun; F12 paused non-M1 capture.
