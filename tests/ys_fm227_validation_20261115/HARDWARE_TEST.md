# Experimental hardware test — FM PR227 + physical SRAM

Status: procedure prepared; RBF qualification and user hardware results are recorded separately in REPORT.md. Do not infer hardware PASS from simulation or compilation.

Use only the uniquely named experimental RBF and SHA256 listed in the final report. Its baseline is FM PR227 at8cd53ccc; its source is the physical-SRAM branch at69edeb48 unless the report explicitly records a later source/patch. Keep the known-good RBF available. Preserve existing savestate files before writing a test slot; use a separate fresh slot for each core/ROM. Do not exchange Japanese/standard/FM-hack or historical-v19 snapshots.

Keep CPU turbo disabled. Record exact ROM hash, NTSC/PAL and region, BIOS enabled/disabled and image hash, mapper options, FM setting, scene and input sequence. The simulator's qualified case uses the standard USA/Europe/Brazil ROM, NTSC/export, BIOS off, ordinary Sega mapper. Do not change configuration between baseline and experimental observations.

1. **Standard Ys:** start a new game and enter the initial playable castle-town screen. On the baseline, SAVE, walk north through the gate to the outdoor coast/bridge scene, settle, LOAD, then move left/right to expose map columns. Repeat with a fresh independent SAVE on the experiment. For the deterministic route after LOAD: neutral5frames, LEFT8, RIGHT80, DOWN16, RIGHT64. The down/right leg clears a tree that otherwise blocks horizontal scrolling. Record the initially correct restored screen and the newly exposed right strip. Expected experiment: no progressive wrong tiles.
2. **FM Restoration v1.2 and Japanese Ys:** repeat the same scene/history/LOAD/movement procedure independently for each ROM, with fresh per-ROM slots. Also confirm music resumes correctly. The supplied FM-hack save is an older-format compatibility input, not a complete-SRAM reference for this test.
3. **Reset then LOAD:** create a fresh first-screen save, reset, LOAD and move through the map. State exactly which reset was used: OSD core reset, reloading the RBF, or rebooting MiSTer. Test at least OSD reset and the reset type that originally failed. Do not group these different histories into one claimed result.
4. **Double Dragon and California Games:** with FM enabled, SAVE during a recognizable musical passage, change history, LOAD repeatedly and compare the resumed music with the FM baseline. Check melody, percussion, sustained notes, channel balance and absence of glitches. Repeat an FM-disabled case to confirm silence/mixer behavior remains correct. Record titles/ROM hashes and settings rather than reporting a generic FM PASS.
5. **Older states:** test a preserved PR227 FM484311 state and an appropriate pre-FM/legacy state. They retain their historical SRAM footprint; missing hidden SRAM cannot be recovered. A LOAD succeeding does not guarantee correct Ys map continuation from an old mapper-disabled save. New484314 saves require the new reader; do not use them as backward-compatible inputs to an older core.

Record per case: RBF SHA, ROM/configuration, independent SAVE slot, exact reset/history, number of LOADs, movement, before/after photos or video, graphics result and FM result. A remaining error should include the earliest visible tile/scene and whether changing environments regenerates it. Hardware remains untested until the user supplies these observations.
