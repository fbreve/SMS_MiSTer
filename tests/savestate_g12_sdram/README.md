# G12 investigation evidence

Scope is investigation only, current committed v16. No production/format edit,
fix prototype, Quartus, staging, commit, push or PR. The report is generated by
`write_report.js` after `audit.js` validates all canonical evidence and unchanged
production. G11, F01/F06 and G08.FM remain outside this investigation.

The confirmed witness captures a naturally paused System E fetch (consumed-T0),
then naturally unpauses the host UI before LOAD. The last real DDRAM response is
delayed by eight legal clocks. Private T1 at raw25 is not a pixel/SDRAM reference
pulse. Phase commit can release before SDRAM samples the read at q0. First running
T2 consumes stale opcode32 instead of23; HL fails to increment. rd_rdy remains
stale-high. No controller/divider/CPU/Pause historical register is forced.
Only the host request cooldown is bypassed, as in the existing replay fixtures.

`running/witness_8_fast0` is the canonical production-flush fault;
`running/witness_0_fast0` is its same-source, full-flush safe control. Both SAVE
images are complete, known and byte-identical. Both run a separate golden T80
with identical restore/enables/mapper/RAM and direct immutable ROM data. That
golden path is an oracle, not a production fix. It agrees with the real CPU
before LOAD, then exposes actual architectural divergence from stale input.
The primary positive campaign separately uses independent uninterrupted physical
SDRAM/CPU references recorded from accepted T+1.

## Fixture scopes

* Root:52 positive timing/data-arrival/stall/System E/shared-memory/history/full-
  flush cases plus two directed pending-PSG/paused-read sanity cases.
* strict/:nine additional transfer/history cases. WRAM high bits distinguish
  both8KiB portions; address/hash/canary patterns, four independent System E bank
  combinations, every-byte counts and request-through-release traces.
* commands/:two independent exact DDR payload-command and image-byte scoreboards.
  The long System E profile uses busy2020/2048 and read latency29; it is slow.
* Unit:every issue phase for10/15-clock references,35 addresses including all25
  one-hot bits, both lanes and high/low/bank boundaries, TAC0/3/7:2625 reads.
* running/:bounded fault/control characterizers. They stop after1000 continuation
  host clocks and do not propose or apply a fix.

Full live-controller and platform distinctions are in `architecture.md` and
`state_inventory.md`. Component arbitrary request phases are not claimed as
naturally accepted CPU SAVE phases. Live SDRAM has fixed CAS2 and no backpressure
input; legal data-arrival variation is separate from DDRAM busy/response timing.
RAM transfer fixtures use synchronous production-equivalent endpoints with
renderers held, rather than repeating complete VDP rendering or sprite proof.
No F06 completeness conclusion is drawn.

## Exact simulation adaptations

Production files remain untouched. The controller adapter only relocates forward
declarations for ModelSim and parameterizes the retained flush interval. Full-
flush representatives and both canonical characterizers set TB_FAST=0.

The SDRAM adapter changes the nonstandard procedural inout declaration into a
separate16-bit procedural drive register plus continuous assignment to the
resolved wire, retaining both original nonblocking drive assignments. It names
the access-manager block for read-only observation. Message2244 is suppressed
for implicit-static initialized locals; their intended static semantics remain.
`audit.js` mechanically checks this exact adapter against current production and
checks all controller copies. It never accepts an altered transition as a fix.

CPU files are the existing observed/qualified ModelSim T80 copies. The unused
block-IO width warning is inherited; tested programs do not depend on Xs or that
unused path. Mapper adaptation adds `when others => null` for nonbinary selectors
that strict ModelSim requires; known normal-case transitions are unchanged.
CPU/register/image/data oracles reject unknown relevant values. Pin DQ can be Z,
and the inactive write-only drive datum can be uninitialized during a read's
non-data phase; neither is used as an equality oracle. ACT/CAS establish every
modeled response before a CPU consumer.

## Reproduction

Installed tools: Node at `C:/Program Files/nodejs/node.exe`, ModelSim Intel FPGA
17.0 at `C:/intelFPGA_lite/17.0/modelsim_ase/win32aloem`. Run from repository root;
PowerShell scripts use `powershell -NoProfile -ExecutionPolicy Bypass -File`.
Do not regenerate or recompile a fixture while a simulation uses its library.

```powershell
node tests/savestate_g12_sdram/prepare.js
node tests/savestate_g12_sdram/plan.js
powershell -NoProfile -ExecutionPolicy Bypass -File tests/savestate_g12_sdram/matrix.ps1 -Compile
powershell -NoProfile -ExecutionPolicy Bypass -File tests/savestate_g12_sdram/matrix.ps1 -Cases sanity_cases.json
node tests/savestate_g12_sdram/prepare_strict.js

powershell -NoProfile -ExecutionPolicy Bypass -File tests/savestate_g12_sdram/matrix.ps1 -Fixture commands -Compile

node tests/savestate_g12_sdram/audit.js

```

The original root campaign used three shards of the same generic runner, with
independent output folders and a shared read-only compiled library. The retained
manifest and scripts allow serial reproduction. `prepare_running.js` lists some
additional planned delays that were not run after confirmation; canonical
reproduction uses only0 and8. A failing characterizer prints `CONFIRMED G12` and
exits successfully because the requested defect reproduction completed. This
marker is never counted as a functional PASS.

## Excluded pilots

Initial compile attempts exposed strict local-static/inout-net rules and unnamed
block observation; only the documented semantic adapters resolved them. An
initial chip fixture incorrectly tied SDRAM init to CPU reset; the ordinary-read
assertion rejected it before the SAVE proof. Correct startup lets initialization
finish naturally while CPU remains reset. Incomplete initial golden/memory runs
and the earlier uninstrumented `normal/` are not canonical case counts.

The first generic runner rejected a successful characterizer's completion string
because it expected `PASS MATRIX`. The dedicated running.ps1 validates the
proper control/defect markers. An early displayed PC field selected SP; canonical
full-flush characterizers select REG[79:64] and the bus confirms003F. Older fast
support is not counted as canonical characterization.

The first System E command observer over-required BE=FF for metadata; production
correctly uses BE=7F for PSG2. `commands/pilots/systeme_metadata_mask.log` retains
that observer failure. Final full-mask assertions apply to RAM payload only;
exact payload address/count/data checks remain strict. Historical completed logs
whose paths have been reused during pilot development are supporting material,
not additional passes. `results.json` counts canonical completed logs only.
