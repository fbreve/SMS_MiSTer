# Shared savestate word buffer: validation and physical comparison

Scope: [fbreve/SMS_MiSTer PR #3](https://github.com/fbreve/SMS_MiSTer/pull/3).
The original RTL is pinned to `ab09fdf41221c9e3e77eee87264a125ba43021fe` and the shared-buffer RTL to `28ead01f7f8709ddda5dc4a63206b9921cb757e0`.
Later commits add only this test/documentation directory. No other optimization is part of the comparison.

## Functional reproduction

Requirements: Git, Node.js (18+), Windows PowerShell and ModelSim Intel FPGA Starter 10.5b with its bundled libraries available. Use a normal clone with both pinned commits present. The scripts work from any working directory and do not read other untracked test directories.

Set `VSIM_EXE` to the simulator executable, or put `vsim.exe` on PATH:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/shared_savestate_word_buffer/run.ps1
```

Alternatively pass `-Vsim <path-to-vsim.exe>`. ExecutionPolicy Bypass applies only to this child process. Each run creates a new ignored `simulations/run-<timestamp>/` directory and refuses an existing attempt. Three independent simulator processes run the retained 16-operation regression, 24-save matrix, and 8-save directed-stall test. `verify.js` requires the expected transaction totals and all six final-word stall coverage markers, then writes hashes and summaries to that attempt's `results.json`.

`fixtures/regression_tb.sv` preserves the controller portion of the prior `feedback_memory_auto` fixture. The two external FM instances and their comparison are omitted because this experiment changes only the controller. FM equivalence is not claimed. No controller timing or state logic is shortened; only the UI request cooldown is bypassed symmetrically. `prepare.js` moves two forward-referenced declarations identically for ModelSim compatibility. Quartus uses the unadapted production blobs.

Additional fixtures are generated by `prepare_focused.js` and `prepare_targeted.js`. They supply different bytes every cycle, including stalled cycles, compare DDRAM payloads/addresses at the receiving edge as well as controller outputs, cover SMS/System E and NVRAM 0/8/16/32 KB, and require stalls before/after registration of final DMA words. The intermediate `directed_tb.sv` is generator input only, never simulated independently.

Functional evidence is retained in `evidence/functional/`; generated HDL, ModelSim libraries and superseded attempts are excluded from Git. See [functional audit](review.md) for the equivalence argument and limits. Tests compare against the original implementation; they are not a formal proof or an independent complete RAM-content oracle.

## Physical reproduction

The configuration follows [OPLL PhaseMemory PR #224](https://github.com/MiSTer-devel/SMS_MiSTer/pull/224): Quartus Prime Lite 17.0.2 Build 602, device 5CSEBA6U23I7, revision SMS, top sys_top, MISTER_FB=1, seeds 1 and 2, fixed BUILD_DATE=261014, original QSF/QIP/SDC/IP and all performance/packing settings. `NUM_PARALLEL_PROCESSORS ALL` is retained. Each of the four builds starts without databases; no historical fit replaces a new endpoint.

```powershell
node tests/shared_savestate_word_buffer/prepare_physical.js
# Set QUARTUS_BIN to the installed Quartus 17.0.2 bin64 directory.
powershell -NoProfile -ExecutionPolicy Bypass -File tests/shared_savestate_word_buffer/build_physical.ps1
node tests/shared_savestate_word_buffer/collect_physical.js
```

`prepare_physical.js` refuses existing build trees. To rerun, use a fresh clone/directory; preserve previous attempts. The build script temporarily maps each seed directory to an unused Z: drive, so both seeds use the same `Z:/baseline` and `Z:/candidate` layout as the earlier PhaseMemory comparison. It never replaces an existing mapping and removes its mapping on exit. Direct map/fit/asm/sta stages bypass only the date-generating preflow. The generated build identifier and JTAG chain are deterministic. No programming step is run.

`physical/input_manifest.json` binds every source blob/hash and both QSF seed settings. `physical/tool_identity.json` records executable hashes; `physical/pr224_reference.json` records the prior configuration and expected historical candidate metrics solely as reproduction controls. The new baseline has exactly the same 203 source files as that prior candidate.

`collect_physical.js` validates source hashes, stage completion, seeds and tools, and preserves compressed full reports/stage logs under `physical/evidence/`. Local implementation databases and bitstreams remain ignored in `physical/runs/`. Positive reported slack does not remove inherited unconstrained timing paths. The final physical report discusses area, timing, warnings and the recommendation.
