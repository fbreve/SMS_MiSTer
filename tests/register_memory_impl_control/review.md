# RegisterMemory implementation-control feasibility and first experiment

Extra effort did not recover setup margin relative to the retained AUTO implementation. AUTO still has no reported scaler retiming transformations. No second experiment was run.

## Selected control and feasibility

The only added assignment is `set_global_assignment -name PHYSICAL_SYNTHESIS_EFFORT EXTRA`, applied to both fresh seed-2 source copies. The retained effective setting was Normal. Production RTL, original QSF/SDC, branch refs and retained databases remain unchanged. The two new variants differ only by the already-qualified RegisterMemory logic-attribute deletion; PhaseMemory remains original in both.

[feasibility.md](feasibility.md) records the actual17.0.2 mechanisms, documented behavior versus hypotheses, and two ranked minimal experiments. Extra effort was ranked first and is the only experiment executed. Placement effort4→6 was ranked second and was not prepared or executed. No unsupported placement region, false path, altered clock/uncertainty, video latency change or seed sweep was used.

Version-specific primary evidence is [assignment_help.log](assignment_help.log), generated by the running Quartus Prime Lite17.0.2 Build602 get_assignment_name_info API, and [documentation_manifest.json](documentation_manifest.json) with installed2017 help paths/hashes and extracted text. The installed help is shared Standard/common content; actual Lite registry support plus effective fitter settings confirm usability. The registry explicitly lists Extra/Fast/Normal and Global scope. Baseline and AUTO final fitter reports both show Extra, seed2, retiming On and placement multiplier4. The fitter reports Info16304 noting the physical-effort override of the High Performance mode's Normal default.

The installed2017 Advanced Fitter Settings help describes Extra as allocating additional compilation work to seek performance, not requiring specific transformations. The installed retiming help describes permission to move registers. The registry describes additional performance-mode and merging/duplication dependencies for general retiming. Gate-level diagnostic help documents example legal-movement restrictions; it does not diagnose these physical Fitter runs. Therefore zero transformations with the global setting On is allowed behavior, not proof that the setting is unsupported or disabled.

The earlier two seeds showed383 reported scaler retiming entries in each baseline versus0 in AUTO. Which internal eligibility, criticality or profitability decision causes the difference remains unreported. A changed-netlist heuristic interaction is plausible; a compiler bug, M10K-wide prohibition or specific reset/clock blocker is unverified. This experiment tests sensitivity to effort only.
