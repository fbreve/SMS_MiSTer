# Proposed restart contract — pre-production gate

Baseline8ffd15e2a7e530c0d77b07c6eeae3e8dc0aa0c8a/v13. No production change has been made. This is a protocol proposal to test, not a declaration that the minimal sprite representation or v14 design is proven.

T is the accepted host edge with an eligible MC1/T2 CPU bus. CPU architecture/context and divider phase are sampled at T; NMI history is normalized over T; VDP/video are post-T values collected at ARM. Guest hold starts immediately after the accepted T edge. If the actual CPU enable is admitted, historical T1/T2 reconstruct the CPU at T-plus. If host Pause suppresses that CPU enable, historical T1 alone reconstructs the held pre-T2 state. Record this distinction independently of the external current UI Pause state. These are preparation cycles, not guest continuation. Committing the phase sampled at T makes the next normal host clock logical T+1, preserving F16's first future sample. Sampling divider phase at ARM instead would skip that logical host clock; that earlier draft is superseded before production edits.

SAVE-only skips CPU reconstruction. It still needs phase/beam commit because arbitrary quiet release is disproven. LOAD preparation must not depend on host Pause admitting ordinary CPU enables: only the bounded historical reconstruction is permitted privately, and it must stop on replay completion. Ordinary guest execution remains paused until the current host UI allows it. No extra guest instruction is authorized by that preparation.

The first prototype will use an external testbench sequencer, the prior diagnostic full sprite side record, and a private five-bit phase side record. It will leave the v13 writer/reader untouched. This is an upper-bound/source-isolation experiment, not a final format proposal. Captured phase plus preparation is evaluated against canonical reconstruction; phase alone has already failed.

Expected bounded liveness under the production WAIT=1/BUSRQ=1 contract: metadata installation after DIRSet falls; at most two effective CPU enable events to complete historical T1/T2, or one when T was suppressed, at period15 in the draft production implementation; a constant handshake to commit phase/beam. One raw private enable can coincide with metadata installation and is suppressed by the wrapper, so bound raw opportunities by three. A production implementation must prove the handoff from memory DMA and preserve F16/GG ordering. Bounds exclude independently unbounded storage busy/capture-window seeking and do not relabel F12 capture progress as restore execution.

## Serialization choices to prove

Literal phase preservation needs five bits for modulo30. However, accepted CPU capture events occur only at phases 0, 10, 20, or 25 across normal, turbo and System E cadences. A proposed two-bit semantic encoding is 00=0, 01=10, 10=20, 11=25. The prototype retains the literal value for diagnosis. A canonical or reconstructed phase could avoid those bits only with a complete boundary/cadence proof; arbitrary quiet phase is insufficient. CPU preparation sequencing is needed under either choice. No phase payload decision is finalized by this document.

The paused-boundary analysis adds one independent historical bit: whether the actual CPU consumed T. A running and a qualifying paused execution can expose the same pre-T CPU snapshot and post-T VDP snapshot while requiring different CPU restart states. External current Pause is deliberately not restored, so it cannot reconstruct that saved event. Proposed v14 word02f is phasebits1:0, SystemE ownershipbit2, consumedCPUbit3, reserved63:4zero. Legacy<=v13 defaults to historical T1/T2, and cannot recover this missing history. Paused capture/unpause tests must prove the new bit before production application.

Sprite scanner state/count/index appear overwritten at x257 after accepted x<=256 with scanner WAITING, but require all-cadence/mode reachability proof. Positions/patterns/enables and width/plane shifts can remain current-line live; derived colors/active/ce_spload do not need duplicate state. Retained address/m2_flags and inactive caches require legal mode-switch consumer-order analysis before omission. The14 collision-delay bits are a shared G04 dependency and cannot silently be dropped or used to close G04. Existing flags must freeze, not be duplicated to repair a hold defect.

Production editing remains gated on baseline reproduction, successful protocol prototypes (including G01/F16 representatives), and a sufficient minimal G06 representation. Quartus remains gated on all required post-fix simulations.

## Final implementation and proof

The preceding text preserves the contract written before production edits. The implemented form is the selected hybrid, with phase sampled at T (not ARM), consumed-CPU bit3, minimal4778-bit record per VDP, and `ST_CPU_PREPARE` / `ST_PHASE_COMMIT`. `clock_phase_ready` is a falling-edge acknowledgment; all raw CEs are forced zero on that phase-install edge. `z80_replay` is the private CPU semantic completion condition. `RestoreHold` prevents external NMI resampling through the last held host clock while allowing NMI metadata installation after DIRSet/GG settlement. Ordinary writes remain held even while CPU read address ownership is restored.

The expanded final gate passed256 logged runtime invocations, including all12 legal quiet transport phases, known physical64-slot images, natural omitted-index histories, dual real VDP/PSG System E, current host Pause/unpause, G01/F16 matrices, the post-synthesis-language-correction equivalence miter and actual64-slot three-distinct-Q replay. Exact counts/hashes are in `simulation_results.json` and `evidence_metrics.json`. Capture seeking may advance CPU/PSG coherently under the already approved F12 exception, but private restore preparation does not tick another guest domain. No universal external-storage latency bound is asserted.

Raw presentation x/y may advance during frozen transport. This does not authorize VDP/sprite/status/pixel guest progression; the captured post-T presentation/beam history is reinstalled before logical release. Both System E VDPs use that common beam but independent state. Mapper and controller interfaces retain their existing restoration strobes/input policy; private preparation performs read setup only, with no new guest mapper/IO/write operation. G02–G05 and G08.release remain open as described in the final review.
